# Decisions

Append-only. One row per decision. Status: `DECIDED`, `PROPOSAL`, `OPEN`.

| ID | Date | Status | Decision | Why | What we gave up / alternatives | Owner |
|---|---|---|---|---|---|---|
| D-001 | 2026-10-19 | DECIDED | Base agent is CARES (router + 5 specialist subagents, plus Off Topic and Ambiguous Question) | Team agreed this is the design to build on for the week | Other individual agent designs. Ideas may be reused | Team |
| D-002 | 2026-10-19 | DECIDED | Headline KPI is customer retention | Switching apps is free, so loyalty is the main thing at risk | Revenue or cost as the main KPI | Team |
| D-003 | 2026-10-19 | DECIDED | Work in this repo, one branch per subagent, one person merges, deploys and activates at the end | Avoids conflicts in the shared org; keeps a reviewable history | Everyone deploying to the shared org | Team |
| D-004 | 2026-10-19 | PROPOSAL | The script decides data and money; the model writes words | Instructions are not guarantees; money and identity must not depend on a prompt | Putting limits and percentages in instruction text | Risk Detection owner |
| D-005 | 2026-10-19 | PROPOSAL | Prefer Flow for maintainability (an admin can read and change it); use Apex where speed matters and Flow is too slow | The customer may not have a dedicated IT team. Apex is hard for non-programmers | Apex everywhere (fast but harder to maintain). Not measured yet | Team to confirm |
| D-006 | 2026-10-19 | PROPOSAL | Refund path cannot be reached before Risk Detection has run (a condition in the router, on a variable set only by an action) | Today the router can send anyone to Refund directly | Routing by text description only | Risk Detection owner |
| D-007 | 2026-10-19 | PROPOSAL | Risk Detection is a silent, deterministic step: the script runs the Flow in `before_reasoning` and moves on to Refund. The model does not talk in this step | It is a lookup, not a conversation. A model turn adds cost, latency and a chance to guess. The common pattern (every box is a chatty subagent) is the wrong fit here | A conversational subagent where the model chooses to call the action. We keep the subagent box so the team structure and ownership stay as agreed | Risk Detection owner |
| D-008 | 2026-10-19 | PROPOSAL | Result has three values (CLEAN, NOT_CLEAN, UNKNOWN). Any problem (no contact, bad window, query error) returns UNKNOWN, and UNKNOWN is treated as not clean | A missing answer must never unlock a better offer | A two-value result where an error looks like clean | Risk Detection owner |
| D-009 | 2026-10-19 | PROPOSAL | Count only cases linked to the verified contact (`ContactId`). Cases of type `Refund / Compensation` are not counted | Counting by account could count other people's cases. A recovery made by CARES must not make the customer look risky next time | Count by account (privacy risk). Count all types (self-counting). Cost: cases with only an account are missed (see G-010) | Risk Detection owner |
| D-010 | 2026-10-19 | PROPOSAL | Lookback window is a variable in the agent (`risk_lookback_days`, default 30) passed to the Flow | The business can change it in one visible place. 30 is a placeholder | Hard-coded in the Flow. Custom metadata (better, not built yet) | Risk Detection owner |
| D-011 | 2026-10-19 | PROPOSAL | Router: `go_to_refund` is only available when `risk_checked` is True. Refund requests go to Risk Detection first, which hands over to Refund | Enforces D-006 with a condition, not with prompt text | Instruction-only routing | Risk Detection owner (needs router owner OK) |
| D-012 | 2026-10-19 | DECIDED | Validate before deploy: local compiler + `sf project deploy start --dry-run --test-level NoTestRun` + `sf agent validate authoring-bundle`. Nothing is deployed from this branch | The org is shared. A dry-run changes nothing | Deploying to test early | Risk Detection owner |
| D-013 | 2026-10-19 | DECIDED (built) | Also count cases that have only an account, but only when the contact is the only contact on that account (then the case can only be that person's). With several contacts, do not count and keep the gap | Real data: cases without a contact sit on 2 accounts. One account has 1 contact (4 cases recovered). The other has 3 contacts (1 case stays invisible). So 4 of 5 missed cases are recovered without mixing people | Count by contact only (simple, misses cases). Count by account always (can mix people, privacy risk). Fixing the link at case creation is still the best fix. Risk: a contact added to the account later changes the answer | Risk Detection owner |
| D-014 | 2026-10-19 | DECIDED for now | Should a contact newer than the lookback window be `UNKNOWN` instead of `CLEAN`? (no history is not a clean history). Not built. Decision: keep `CLEAN` for now and ask Pronto | A new customer with no cases has no record to call clean. Rewarding them risks giving the better offer to anyone who just signed up | Today they are `CLEAN`. If we add the rule, every contact in the shared org (all created within the last 30 days) becomes `UNKNOWN`, so tests would not show any `CLEAN`. Needs a business answer and real data | Team / Pronto |
| D-015 | 2026-10-19 | PROPOSAL (built) | Put the gate at the destination: Refund starts with `if risk_checked == False: transition to risk_detection`. The router gate stays as a second layer | One check at Refund covers every route (router, Stolen & Delayed, future ones). A gate on each door leaves any new door open | Gate only in the router (misses other routes). Cost: it edits a small part of the Refund block, which belongs to another owner, and could loop if the action fails without setting `risk_checked` (G-020) | Risk Detection owner (needs Refund owner OK) |
| D-016 | 2026-10-19 | DECIDED | Every case type counts as an issue except `Refund / Compensation`, and closed cases count too. Placeholder until Pronto gives a rule | Simple, explainable, and the recovery exclusion avoids self-counting (D-009) | A list of counting types in configuration; ignoring closed cases. Neither is built | Risk Detection owner |
| D-017 | 2026-10-19 | DECIDED | Simulated preview (no live actions, nothing published) is allowed for testing. Deploy, publish, activate and test data in the shared org still need the team | The preview proves routing and gates and changes no metadata | Waiting for a deploy before testing anything | Risk Detection owner |
| D-018 | 2026-10-19 | OPEN | Option, not built: make the Refund gate depend on the action result (`risk_status` different from its starting value) instead of `risk_checked` | If the action does not run, the gate stays closed. Closes G-022 by design | Keep `risk_checked` (current). Cost of the option: possible loop if the action fails (G-020). Needs a live run or a preview to choose | Risk Detection owner |
| D-019 | 2026-10-19 | DECIDED | Refund handles four outcomes: Stolen and Delayed (from Stolen & Delayed Orders), Wrong/Missing Items and Quality Issue (Refund classifies). Wrong/missing and quality are paid on the affected items only; stolen and delayed on the whole order | Matches the diagram. Paying the whole order for one bad item would overpay | Whole-order value for every outcome. Delayed handled by a person only | Refund owner |
| D-020 | 2026-10-19 | PROPOSAL | Refund actions are invocable Apex stubs with hardcoded values for now | Unblocks the agent and its tests while the policy objects (D-024) don't exist. The contract (inputs, outputs) is final; only the inside changes | Flow, preferred by D-005, for the real logic. To decide when the stubs are replaced | Refund owner |
| D-021 | 2026-10-19 | PROPOSAL (built) | The script runs the offer calculation once, as soon as the outcome is known. Issue is only available after an explicit yes to the repeated option and amount, only once, and every input comes from variables | Applies D-004: the model can't pick, change or retype an amount | Letting the model call the calculation, or slot-fill amounts on issue | Refund owner |
| D-022 | 2026-10-19 | DECIDED (built) | Two confirm actions (`confirm_refund`, `confirm_store_credit`) that set the choice as a literal, not one action where the model fills the value | In preview the model wrote free text ("Store credit of $18.0") instead of `Store_Credit` | One slot-filled confirm action (simpler, unreliable) | Refund owner |
| D-023 | 2026-10-19 | DECIDED (built) | After issuing, Refund shows the confirmation and reference, clears its own variables in `after_reasoning`, and does not transition.
